# c11n Reboot Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Rebuild c11n as a zero-integration stakeholder review tool: any web project (Vue first) is served through a Caddy reverse proxy that injects a comment/annotation overlay — the reviewed site needs no code changes.

**Architecture:** Three pieces. (1) **Caddy** (with the official `replace-response` plugin — no custom Go) reverse-proxies the site under review and injects one `<script>` tag into HTML responses; it also serves the overlay bundle and proxies PocketBase under the same origin, killing CORS entirely. (2) **PocketBase** is the whole backend for v1: auth, SQLite storage, and realtime SSE subscriptions. All data access in the overlay goes through one `api.ts` wrapper so a later swap to a custom Go backend touches exactly one module. (3) The **overlay** is a Vue 3 app built as a single IIFE bundle, mounted in a shadow DOM so its styles can't collide with the reviewed app.

**Tech Stack:** Caddy 2 + `caddyserver/replace-response`, PocketBase (latest), Vue 3 + Vite (lib/IIFE build), Pinia, `@medv/finder` (unique CSS selector generation), `@floating-ui/dom` (popup positioning), Vitest, Docker Compose, GitHub Actions.

## Key design decisions

| Decision | Choice | Why |
|---|---|---|
| Injection | Caddy `replace-response` rewrites `</head>` → `<script src="/__c11n/overlay.js" defer></script></head>` | Zero custom Caddy plugin code; works on any HTML upstream (dev server, preview build, staging) |
| Same-origin | Caddy serves `/__c11n/*` (overlay assets) and `/__c11n/pb/*` (PocketBase API) on the review host | No CORS, no cookies-across-origins, SSE just works |
| Anchoring | `@medv/finder` generates a unique selector at comment time; we also store tagName + trimmed text + bounding box as fallback/repair data | Battle-tested library instead of hand-rolled selector walker (old prototype hand-rolled it) |
| Isolation | Overlay mounts into a `<div>` with `attachShadow({mode:'open'})`; all CSS injected into the shadow root | Reviewed app's CSS and ours can't fight |
| Comments model | `comments` (thread root, anchored to selector+path) + `replies` (flat under a comment) | Matches "stakeholders ask questions, team answers"; YAGNI on nesting |
| Page identity | Comments keyed by normalized `path + sorted query` (hash stripped, tracking params dropped) | Same normalization idea as the old prototype; SPA-friendly |
| Realtime | PocketBase `subscribe()` on `comments`/`replies` filtered by project | Built-in SSE; no WebSocket server to write |
| Backend swap escape hatch | Overlay talks only to `src/lib/api.ts` (interface `C11nBackend`) | Swapping PocketBase → custom Go = reimplement one file |
| Auth (v1) | PocketBase email/password users, created by the project owner in the PB admin UI; overlay shows a login panel | Simplest thing that gives named commenters; magic links later |

**API rules (all three collections):** list/view/create for `@request.auth.id != ""`; update/delete for `@request.auth.id = author.id` (projects: superuser-only writes). Comments additionally allow `resolved` toggle by any authenticated user (v1 simplicity — reviewers can resolve).

### Task 4: Caddy with replace-response injection

**Objective:** Caddy proxies an upstream, injects the overlay script tag into HTML, serves overlay assets, and proxies PocketBase — all same-origin.

**Files:**
- Create: `deploy/caddy/Dockerfile`
- Create: `deploy/Caddyfile`
- Create: `deploy/docker-compose.yml`
- Create: `deploy/.env.example` (`C11N_UPSTREAM=http://demo:5173`)

**Caddy Dockerfile:**
```dockerfile
FROM caddy:2-builder AS builder
RUN xcaddy build --with github.com/caddyserver/replace-response
FROM caddy:2
COPY --from=builder /usr/bin/caddy /usr/bin/caddy
```

**Caddyfile:**
```caddyfile
{
	order replace after encode
}

:8080 {
	# PocketBase API + realtime, same-origin under /__c11n/pb/
	handle_path /__c11n/pb/* {
		reverse_proxy pocketbase:8090 {
			flush_interval -1   # SSE
		}
	}

	# Overlay bundle
	handle_path /__c11n/* {
		root * /srv/overlay
		file_server
	}

	# The site under review, with script injection
	handle {
		reverse_proxy {$C11N_UPSTREAM} {
			header_up Accept-Encoding identity   # don't let upstream gzip; replace needs plaintext
		}
		replace stream {
			`</head>` `<script src="/__c11n/overlay.js" defer></script></head>`
		}
	}
}
```

**docker-compose.yml:** services `caddy` (build deploy/caddy, ports 8080:8080, volumes Caddyfile + `../packages/overlay/dist:/srv/overlay:ro`, env C11N_UPSTREAM), `pocketbase` (build deploy/pocketbase, volume `pb_data`, port 8090:8090 for admin UI only).

**Verification (before the overlay exists, use a stub):**
```bash
mkdir -p packages/overlay/dist && echo 'console.log("c11n overlay stub")' > packages/overlay/dist/overlay.js
cd deploy && cp .env.example .env
# point C11N_UPSTREAM at any HTML upstream, e.g. python3 -m http.server, then:
docker compose up -d --build
curl -s http://localhost:8080/ | grep '__c11n/overlay.js'     # tag injected ✓
curl -s http://localhost:8080/__c11n/pb/api/health            # PB reachable same-origin ✓
```

**Pitfalls to note in docs:** (a) `replace` only rewrites when the upstream response is uncompressed — hence `Accept-Encoding identity`; (b) PB admin UI is used at :8090 directly, only the API goes through the proxy subpath; (c) exact `replace` block syntax should be validated against the plugin README at build time — if `stream` placement differs, adjust.

Deps: `vue`, `pinia`, `pocketbase`, `@medv/finder`, `@floating-ui/dom`. Dev: `vite`, `@vitejs/plugin-vue`, `typescript`, `vue-tsc`, `vitest`, `jsdom`.

**src/main.ts (bootstrap):**
```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import cssText from './styles.css?inline'

function mount() {
  if (document.getElementById('c11n-root')) return
  const host = document.createElement('div')
  host.id = 'c11n-root'
  document.body.appendChild(host)
  const shadow = host.attachShadow({ mode: 'open' })
  const style = document.createElement('style')
  style.textContent = cssText
  shadow.appendChild(style)
  const target = document.createElement('div')
  shadow.appendChild(target)
  createApp(App).use(createPinia()).mount(target)
}

document.readyState === 'loading'
  ? document.addEventListener('DOMContentLoaded', mount)
  : mount()
```
Note: Vite lib mode inlines component CSS; verify the built bundle has no separate .css request, else add `vite-plugin-css-injected-by-js`.

**Verify:** `npm run build -w packages/overlay` → single `dist/overlay.js`; restart compose stack; loading the proxied site logs the overlay mounting and shows an empty shadow-DOM host in devtools.

## Risks & tradeoffs

1. **`replace-response` syntax/behavior drift** — validate the Caddyfile against the plugin README during Task 4; the `Accept-Encoding identity` header is load-bearing (compressed upstreams won't match `</head>`).
2. **Selector fragility across deploys** — mitigated by text fallback + "orphaned" UX, not solved. Good enough for review cycles; revisit with content-hash anchoring if it bites.
3. **PocketBase under a subpath** — API works with `strip_prefix`; the admin UI does not, so admin happens on :8090 directly. Documented.
4. **Sites with aggressive CSP** — upstream `Content-Security-Policy` headers may block the injected script; v1 answer: Caddy strips/relaxes CSP on proxied responses (add `header_down -Content-Security-Policy` and document the tradeoff — this proxy is for staging review, not production).
5. **PocketBase realtime through proxies** — `flush_interval -1` handles it; if SSE misbehaves, fall back to polling in `api.ts` (interface already hides transport).
6. **Later Go swap** — contained by `C11nBackend`; the Go server would reimplement 8 methods + SSE.

## Open questions (non-blocking, defaults chosen)

- Guest commenting (name-only, no account)? **Default: no for v1** — PB users only.
- Screenshot capture with comments? **Deferred** (html2canvas is heavy; anchorMeta.rect covers most needs).
- Multi-project routing (one proxy, many upstreams)? **Deferred**; v1 is one compose stack per reviewed site.
