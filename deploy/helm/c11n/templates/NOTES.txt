Two workloads: Deployment {{ include "c11n.fullname" . }}-caddy (the proxy) and

1. THE OWNER SIGN-IN LINK
   The first owner is created on PocketBase's FIRST HTTP REQUEST (its own
   readiness probe triggers it), and the one-time link is printed to the
   pocketbase container's stdout. It is in no other place - copy it now:

     kubectl logs statefulset/{{ include "c11n.fullname" . }}-pocketbase -c pocketbase | grep 'c11n bootstrap'

   The pod is {{ include "c11n.fullname" . }}-pocketbase-0 if you prefer to name
   it. If it has already restarted, use --previous. The link is single use and
   expires after {{ .Values.invite.ttlHours }}h; if it is lost, mint another
   from an owner session (Invite in the overlay) - there is no email channel.

2. SIGN IN
   Open the link, click "Continue to review". Everyone else is invited from the
   overlay's sidebar by an owner or team member.

3. POCKETBASE ADMIN UI (superuser)
   Not on {{ .Values.host }} (Caddy answers 404). Port-forward the Service:

     kubectl port-forward svc/{{ include "c11n.fullname" . }}-pocketbase 8090:8090
     # then http://127.0.0.1:8090/_/

   A Service port-forward reaches the (single) pocketbase pod whatever it is
   called. If your CNI filters port-forward traffic under the chart's
   NetworkPolicy - unusual, but CNI-dependent - see docs/runbook.md section 9.
